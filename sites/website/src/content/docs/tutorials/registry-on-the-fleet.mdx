`examples/registry/` runs a real Podman registry on a golem-managed box, and
uses it from two others. It is the first half of golem's dogfood loop: one VM
*hosts* a registry, another *pushes* to it, a third *pulls* — no shared L2
segment, just golem and QEMU's host-gateway. Start with the
[VM harness](/tutorials/the-vm-harness/) loop; this builds on it.

## The registry, as one `Workload`

`registry.emet` is a single [`Quadlet.Workload`](/reference/workloads/) — the
docker.io `registry:2` image on `:5000`, backed by a named volume, internally
exposed:

```emet
import Quadlet exposing
  ( image, tcp, Restart(..), Access(..), Relabel(..)
  , fromVolume, Expose(..), Workload(..), workloadGlyphs )

registry : Workload
registry =
  Workload
    { name = "registry"
    , image = image "docker.io/library" "registry" "2"
    , env = []
    , ports = [ tcp 5000 5000 ]
    , volumes =
        [ fromVolume "golem-registry-data" "/var/lib/registry" ReadWrite Private ]
    , restart = Always
    , expose = Internal
    }

main : List Scroll
main = [ scroll { name = "registry", glyphs = workloadGlyphs registry } ]
```

It lowers to five glyphs — the podman package, the `golem-registry-data.volume`
unit, the `.container` quadlet, its service, and the internal firewall opening:

```
planned scrolls (1):
  scroll `registry` (5 glyphs):
    * ensure apt package `podman` installed
    * ensure file `/etc/containers/systemd/golem-registry-data.volume` (mode 0644)
    * ensure file `/etc/containers/systemd/registry.container` (mode 0644)
    * enable + start systemd unit `registry.service`
    * ensure file `/etc/nftables.d/registry-5000.nft` (mode 0644)
```

## Deploy it to a box

<Steps>
1. **Boot the registry VM, publishing its port to the host.** `--publish` forwards
   an extra guest port so other guests can reach it:

   ```bash
   fleet up --hosts registry --publish registry=5000:5000
   ```

2. **Deploy golemd and apply the scroll:**

   ```bash
   fleet deploy --hosts registry
   fleet apply examples/registry/registry.emet --hosts registry
   ```

3. **Confirm the registry is serving.** The port is published to the host, so
   curl it from your laptop:

   ```bash
   curl -s http://127.0.0.1:5000/v2/ && echo OK
   fleet ssh registry systemctl status registry.service
   ```
</Steps>

## Reach it from another machine

Each guest runs behind user-mode (SLIRP) networking and is isolated from the
others — only ssh and golemd are forwarded by default. Two facts bridge them:

- `up --publish registry=5000:5000` binds the host's `127.0.0.1:5000` to the
  registry guest's `:5000`.
- In SLIRP, every guest reaches the host at `10.0.2.2`.

So any guest reaches the registry's *published* port at **`10.0.2.2:5000`** — the
connection lands on the host loopback, which QEMU forwards into the registry
guest. That is the rendezvous `clients.emet` uses. It provisions `builder` and
`puller` boxes with podman and an insecure-registry drop-in pointing at
`10.0.2.2:5000`:

```emet
registryEndpoint : String
registryEndpoint = "10.0.2.2:5000"

clientGlyphs : List Glyph
clientGlyphs =
  [ aptPackage { name = "podman" }
  , file
      { path = "/etc/containers/registries.conf.d/golem-registry.conf"
      , contents = insecureConfContents      -- marks 10.0.2.2:5000 insecure (plain HTTP)
      , mode = "0644"
      }
  ]

main : List Scroll
main = [ builder, puller ]     -- both scrolls are clientGlyphs
```

<Steps>
1. **Boot the two client VMs and provision them:**

   ```bash
   fleet up --hosts builder,puller
   fleet deploy --hosts builder,puller
   fleet apply examples/registry/clients.emet --hosts builder,puller
   ```

2. **Push from the builder** — tag any image at the golem registry and push over
   the host gateway:

   ```bash
   fleet ssh builder -- podman pull docker.io/library/hello-world:latest
   fleet ssh builder -- podman tag docker.io/library/hello-world:latest 10.0.2.2:5000/hello:latest
   fleet ssh builder -- podman push 10.0.2.2:5000/hello:latest
   ```

3. **Pull from the puller** — a different machine, same registry:

   ```bash
   fleet ssh puller -- podman pull 10.0.2.2:5000/hello:latest
   ```
</Steps>

One golem-hosted registry, shared across three machines, no shared network
segment required.

<Aside type="note" title="Insecure on purpose">
  The drop-in marks the registry insecure so podman pushes over plain HTTP —
  fine for an ephemeral local fleet, not for anything real. Registry auth and TLS
  are their own concern, out of scope for the dogfood loop.
</Aside>

## Explore from here

- **Watch the diff.** Re-apply `registry.emet` after bumping the image tag to
  `registry:3` — only the `.container` glyph's content id changes, so only that
  glyph is replaced.
- **Reverse it.** Apply an empty scroll to `registry` and watch golem stop the
  service, remove the quadlet and `.volume` units, close the firewall port, and
  remove podman — each undone because golem recorded it.
- **Inspect the volume.** `fleet ssh registry -- ls /var/lib/registry` — the
  named volume that survives a container restart.
