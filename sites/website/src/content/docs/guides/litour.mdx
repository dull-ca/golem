The capstone example is the [lichess](https://lichess.org) fleet: six hosts
running dozens of containerized services behind nginx ingress. It lives in
`examples/lichess/` and compiles as-is. This is a tour of how it is built —
a shared library of abstractions, a fleet that uses them, and the glyphs it
all lowers to.

The example is three files:

- `Fleet.emet` — shared fleet-wide facts.
- `Lichess.emet` — the library: `Workload`, `Service`, `Ingress`
  abstractions and their glyph-lowering.
- `fleet.emet` — the fleet itself: every host as a `Scroll`.

## Shared facts as a module

Cross-host facts are ordinary Emet values in an imported module — no
placeholder substitution, no templating:

```elm
module Fleet exposing (internalNetwork, endpoint)

internalNetwork : String
internalNetwork = "10.0.0.0/8"

endpoint : String -> Int -> String
endpoint address port = "${address}:${String.fromInt port}"
```

`internalNetwork` is a `String` any module can import and use. If another
host needs to reach a service, that address is a value passed as data and
checked by the type system — not a string the resolver hopes to fill in
later.

## The library: three abstractions

`Lichess.emet` defines the vocabulary and its lowering. Each abstraction is a
record type plus a function returning `List Glyph`.

### Workload — a plain container

```elm
type Workload = Workload { name : String, image : String }

containerGlyphs : String -> String -> List Glyph
containerGlyphs name image =
  [ aptPackage { name = "podman" }
  , file
      { path = quadletPath name
      , contents = quadletContents name image
      , mode = "0644"
      }
  , systemdService { unit = serviceUnit name }
  ]

workloadGlyphs : Workload -> List Glyph
workloadGlyphs w =
  case w of
    Workload spec -> containerGlyphs spec.name spec.image
```

A workload lowers to three glyphs: podman, the quadlet `file`, the unit.

### Service — a workload that opens a port

```elm
type Service = Service { name : String, image : String, port : Int }

serviceGlyphs : Service -> List Glyph
serviceGlyphs s =
  case s of
    Service spec ->
      List.append
        (containerGlyphs spec.name spec.image)
        [ file
            { path = nftablesPath spec.name
            , contents = firewallOpening spec.name spec.port
            , mode = "0644"
            }
        ]
```

A service is a workload plus one `file` glyph carrying an nftables fragment
that opens the port to `internalNetwork`. Four glyphs.

### Ingress — public HTTPS via nginx

```elm
type Ingress = Ingress { name : String, service : String, from : String, port : Int }

ingressGlyphs : Ingress -> List Glyph
ingressGlyphs i =
  case i of
    Ingress spec ->
      [ aptPackage { name = "nginx" }
      , file
          { path = nginxSitePath spec.name
          , contents = nginxSite spec.name spec.service
          , mode = "0644"
          }
      , file
          { path = nftablesPath "ingress-${spec.name}"
          , contents = firewallOpening "ingress ${spec.name}" spec.port
          , mode = "0644"
          }
      , lineInFile
          { path = "/etc/nftables.d/ingress.nft"
          , line = ingressOpening spec.name spec.port
          }
      , systemdService { unit = serviceUnit "nginx" }
      ]
```

Ingress is the one place all four glyphs appear: the nginx package, the site
`file`, a per-ingress firewall `file`, a shared-file `lineInFile` (one accept
rule appended to `/etc/nftables.d/ingress.nft`), and the nginx unit. The
site config and firewall rules are rendered by `String.join` at compile time
— the `nginxSite` and `firewallOpening` helpers are plain string functions.

<Aside type="note" title="lineInFile vs file, on purpose">
  The per-ingress firewall is its own `file` — golem owns it entirely. The
  shared `ingress.nft` gets a `lineInFile` — golem appends one line and, on
  reverse, removes only that line, leaving every other ingress's line intact.
  That distinction is why both primitives exist. See
  [The four glyphs](/reference/primitives/).
</Aside>

## The host binder

One helper turns a name and its glyphs into a scroll:

```elm
host : String -> List Glyph -> Scroll
host name glyphs = scroll { name = name, glyphs = glyphs }
```

## The fleet

`fleet.emet` imports the library and defines each host as a `Scroll`. A host
is a `List.concat` of abstraction calls:

```elm
module Main exposing (..)

import Lichess exposing
  ( Workload(..), Service(..), Ingress(..)
  , workloadGlyphs, serviceGlyphs, ingressGlyphs, host )

manta : Scroll
manta =
  host "manta"
    (List.concat
      [ workloadGlyphs (Workload { name = "leroyjenkins-lila", image = "lichess-org/leroyjenkins:latest" })
      , serviceGlyphs (Service { name = "lila", image = "lichess-org/lila:latest", port = 9663 })
      , serviceGlyphs (Service { name = "redis-server", image = "redis:7", port = 6379 })
      , ingressGlyphs (Ingress { name = "lichess.org", service = "lila", from = "world", port = 443 })
      ])

scaly : Scroll
scaly = host "scaly" (workloadGlyphs (Workload { name = "fishnet", image = "lichess-org/fishnet:latest" }))

main : List Scroll
main = [ scaly, manta, orbit, talos, kaiju, zulip ]
```

Six hosts, one `main`. `scaly` runs a single networkless workload; `manta`
fronts lila with ingress; `kaiju` is one mongo service; `talos` runs the
monitoring stack. Every host reads as the shapes you care about, and every
shape lowers to the four glyphs.

## Compile and apply

```bash
# The whole fleet to a binary manifest.
emetc build examples/lichess/fleet.emet -o fleet.manifest

# Eyeball one host's plan.
emetc build examples/lichess/fleet.emet --text

# Ship it. The agent for host 'manta' selects manta's scroll.
golemctl apply fleet.manifest http://127.0.0.1:7474
```

The manifest carries all six scrolls. Each `golemd` selects its own by
`--host` name and ignores the rest — see
[Manifest format](/reference/bundle-format/). `examples/lichess/run.sh`
drives this end-to-end against a golemd container.

## What you just saw

The fleet is authored in the vocabulary of the problem — workloads,
services, ingresses, an internal network — and none of that vocabulary
reaches the agent. It all lowers to `aptPackage`, `systemdService`, `file`,
and `lineInFile`, checked by Emet's type system on the way down.

- **Abstractions are functions.** `Workload`, `Service`, `Ingress` are Emet
  types and functions in a library module, not engine features.
- **Cross-host facts are values.** `internalNetwork` is imported and passed
  as data — no placeholder resolution.
- **Rendering is compile-time.** nginx sites and nftables rules are built by
  `String.join`; the glyphs carry final strings.
- **Upgrade and removal are content-addressed.** Bump an image tag,
  recompile, re-apply — only the changed glyphs are replaced. See
  [Reversible reconcile](/reference/honest-convergence/).
