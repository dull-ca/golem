There is no built-in "container" or "service" in golem. You build them in
Emet, and they lower to the [four glyphs](/reference/primitives/). This
guide builds a `service` abstraction the way the real
[lichess fleet](/guides/litour/) does — a container workload plus a firewall
fragment — and shows exactly which glyphs it produces.

All the Emet here is from `examples/lichess/Lichess.emet`; it compiles.

## A container workload

A podman container on Debian is three glyphs: the `podman` package, a
quadlet `.container` file that systemd turns into a unit, and the unit
itself. The file's contents are built by the language:

```elm
quadletPath : String -> String
quadletPath name = "/etc/containers/systemd/${name}.container"

serviceUnit : String -> String
serviceUnit name = "${name}.service"

quadletContents : String -> String -> String
quadletContents name image =
  String.join "\n"
    [ "[Unit]"
    , "Description=Golem workload: ${name}"
    , ""
    , "[Container]"
    , "Image=${image}"
    , "ContainerName=${name}"
    , ""
    , "[Service]"
    , "Restart=always"
    , ""
    , "[Install]"
    , "WantedBy=multi-user.target default.target"
    ]

containerGlyphs : String -> String -> List Glyph
containerGlyphs name image =
  [ aptPackage { name = "podman" }
  , file
      { path = quadletPath name
      , contents = quadletContents name image
      , mode = "0644"
      }
  , systemdService { unit = serviceUnit name }
  ]
```

`containerGlyphs "lila" "lichess-org/lila:latest"` is now your word for "a
container workload." It returns a `List Glyph` — nothing golem-special, just
data.

## A service = a workload + a firewall

A service is a workload that also opens a port to the internal network. Model
it as a record type and add one `file` glyph that drops an nftables
fragment:

```elm
import Fleet exposing (internalNetwork)

type Service = Service { name : String, image : String, port : Int }

nftablesPath : String -> String
nftablesPath name = "/etc/nftables.d/${name}.nft"

firewallOpening : String -> Int -> String
firewallOpening name port =
  String.join "\n"
    [ "table inet filter {"
    , "  chain input {"
    , "    tcp dport ${String.fromInt port} ip saddr ${internalNetwork} accept comment \"${name}\""
    , "  }"
    , "}"
    ]

serviceGlyphs : Service -> List Glyph
serviceGlyphs s =
  case s of
    Service spec ->
      List.append
        (containerGlyphs spec.name spec.image)
        [ file
            { path = nftablesPath spec.name
            , contents = firewallOpening spec.name spec.port
            , mode = "0644"
            }
        ]
```

`internalNetwork` comes from a shared `Fleet` module (`"10.0.0.0/8"`) — a
plain imported value, not a magic reference. That is how cross-host facts are
shared: as ordinary Emet values, checked by the type system.

## Use it in a fleet

```elm
lila : Scroll
lila =
  scroll
    { name = "app-01"
    , glyphs =
        serviceGlyphs (Service { name = "lila", image = "lichess-org/lila:latest", port = 9663 })
    }

main : List Scroll
main = [ lila ]
```

## What it lowers to

`serviceGlyphs (Service { name = "lila", … port = 9663 })` produces four
glyphs — check with `emetc build … --text`:

| Glyph | Key | Comes from |
| --- | --- | --- |
| `aptPackage { name = "podman" }` | `apt:podman` | `containerGlyphs` |
| `file /etc/containers/systemd/lila.container` | `file:/etc/containers/systemd/lila.container` | the quadlet |
| `systemdService { unit = "lila.service" }` | `systemd:lila.service` | the workload unit |
| `file /etc/nftables.d/lila.nft` | `file:/etc/nftables.d/lila.nft` | the firewall opening |

Every field is a concrete string. The quadlet body and the nftables rule
were rendered by `String.join` at compile time; the agent sees only the final
text.

<Aside type="note" title="The agent never learned the word 'service'">
  `golemd` reconciles four glyphs. "Service," "workload," and "firewall
  opening" are your Emet vocabulary — they exist only in the source and
  vanish at the manifest boundary. That is why the agent stays small: no new
  resource kind, ever.
</Aside>

## Same abstraction, many services

Because `serviceGlyphs` is a function, a whole host is a `List.concat` of
calls:

```elm
scaly : Scroll
scaly =
  scroll
    { name = "scaly"
    , glyphs =
        List.concat
          [ serviceGlyphs (Service { name = "lila-http",  image = "lichess-org/lila-http:latest",  port = 9080 })
          , serviceGlyphs (Service { name = "lila-gif",   image = "lichess-org/lila-gif:latest",   port = 6175 })
          ]
    }
```

Change the image tag, recompile, re-apply — only the changed glyphs get new
content ids and are replaced. See [Applying changes](/getting-started/applying/).
