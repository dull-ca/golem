# SSH-Tunneled Access Control Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** golemd listens loopback-only behind a shared-secret bearer gate; golemctl reaches it over the operator's existing SSH connection; the VM fleet rehearses the same posture end to end.

**Architecture:** Three independent seams per ADR 0042: an axum middleware in golemd comparing `Authorization: Bearer` against a token file in constant time; a `Conn` abstraction in golemctl that owns base-url + token + (for `ssh` targets) a child `ssh -N -L` tunnel whose lifetime brackets the verb; harness provisioning that generates the token, deploys loopback-bound daemons, and emits an ssh-form inventory.

**Tech Stack:** Rust (axum 0.7, reqwest, clap), OpenSSH client as a spawned subprocess (no SSH library), Python stdlib for the harness.

## Global Constraints

- Zero comments in implementation code (`lw:implementer`); a documenter pass owns all comments afterward.
- No new heavyweight dependencies: constant-time compare is hand-rolled (xor-fold), SSH is the system `ssh` binary, token generation is `secrets.token_urlsafe(32)`.
- No token file configured in golemd = gate off (dev/test posture); `--auth-token-file` / `[auth] token_file` present = every route gated, no exceptions.
- The token never appears in argv, logs, error bodies, or `--json` output.
- Existing `http://` targets and the no-auth flow keep working byte-identically (backward compatible until a token is configured).
- Workspace stays green after every task: `cargo test -p <crate>`, `cargo clippy -p <crate> --lib -- -D warnings`, `cargo fmt --check`; harness tasks run the unittest suite.
- Commit per task via `lw:historian` on branch `claude/ssh-auth` (conventional commits, body carries the why).

- Produces: 401 body is the existing `ApiError` shape: `{"kind":"unauthorized","message":"missing or invalid bearer token — golemd requires Authorization: Bearer <token> (see --auth-token-file)"}`. The message never echoes the presented or expected token.
- Constant-time compare (hand-rolled, both directions length-guarded):

```rust
fn token_matches(presented: &str, required: &str) -> bool {
    let (p, r) = (presented.as_bytes(), required.as_bytes());
    if p.len() != r.len() {
        return false;
    }
    p.iter().zip(r).fold(0u8, |acc, (a, b)| acc | (a ^ b)) == 0
}
```

- [ ] Config-level tests in `config.rs`: `[auth] token_file` parses; absent = `None`.
- [ ] Startup behavior in `main.rs`: token file read once, trimmed (`trim_end`), empty after trim = error mentioning the path.
- [ ] Implement middleware; verify; clippy/fmt.

**Interfaces:**
- Produces:

```rust
pub struct Tunnel { child: std::process::Child, pub local_port: u16 }
impl Tunnel {
    // picks a free port by binding 127.0.0.1:0 and dropping the listener,
    // spawns: ssh -N -L 127.0.0.1:{local}:127.0.0.1:{remote} [-p ssh_port] {ssh_args...} {destination}
    // then polls TcpStream::connect(local) until it accepts (250ms interval, 10s budget);
    // a child that exits before the port opens is an error carrying ssh's stderr.
    pub fn open(destination: &str, ssh_port: Option<u16>, remote_port: u16, ssh_args: &[String], ssh_bin: &str) -> Result<Tunnel>;
}
impl Drop for Tunnel { /* kill + wait the child */ }
```

- ControlMaster reuse needs no code: the spawned `ssh` honors the operator's config, so an existing master makes the forward instant. `ssh_bin` is parameterized only so tests can substitute a fake.
- [ ] Failing tests: inventory ssh table parsing (all fields, defaults, url+ssh conflict error); `ssh://` addr parsing (user@, port, defaults); `Tunnel::open` against a fake `ssh_bin` (a tiny shell script the test writes to a tempdir: it binds the requested local port via `nc -l` — or a second fake that exits 1 immediately to assert the stderr-carrying error path).
- [ ] Fleet fan-out: one tunnel per `Ssh` host, opened concurrently inside each host task, dropped at task end; `fleet status` for an unreachable ssh host reports `unreachable: <concise ssh error>` through the existing `concise_error`.
