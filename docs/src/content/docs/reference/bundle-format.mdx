A bundle is the operator's instruction to the agent for one specific host.
The Nickel toolkit produces it (called via `golemctl eval`); `golemd`
applies it.

## Top-level shape

```json
{
  "version": 1,
  "node": "box-01",
  "claims": [ ... ],
  "handlers": [ ... ]
}
```

Then signed:

```json
{
  "bundle": { ... },
  "signature": "hex-encoded ed25519 signature over canonical_json(bundle)",
  "signer": "hex-encoded ed25519 public key"
}
```

The agent verifies `signature` against `signer` over the canonical bytes of
`bundle`, checks `signer` is in `/etc/golem/trusted-keys`, then applies.

## `version`

A monotonically-increasing integer. The agent rejects any bundle whose version
is `<= last_applied_version`. There's no rollback mechanism — to undo a
deploy, push a *newer* bundle that describes the previous state.

Operators don't type version numbers. The Nickel doesn't include a
`version` field; `golemctl apply` queries each target host's
`/status`, computes `max(last_applied) + 1` across the apply set, and
bakes it in before signing. Version numbers are bookkeeping the system
owns.

## `node`

The agent's identity (the host name). Must match the agent's `--node`
flag (or `GOLEM_NODE`). Bundle for a different host → 400.

## `claims`

An array of declarative claims. The kinds the agent understands:

### `file`

```json
{
  "id":   { "kind": "file", "key": "/etc/nginx/sites-enabled/hello.example.com.conf" },
  "kind": "file",
  "spec": {
    "path":    "/etc/nginx/sites-enabled/hello.example.com.conf",
    "content": "...",
    "mode":    420,
    "owner":   "root",
    "group":   "root",
    "marker":  "Owned"
  },
  "owners": ["ingress/edge-01"],
  "after": []
}
```

- `mode` is decimal (`420` = `0o644`). JSON has no octal.
- `marker` is `"Owned"` today. `"Merge"` is reserved for managing a
  marker-delimited fragment of a file (`/etc/sysctl.conf`-style).
- Files larger than 1 MiB at capture time are refused (the agent returns
  `CaptureError::TooLarge` on the claim and skips it).

### `apt_package`

```json
{
  "id":   { "kind": "apt_package", "key": "nginx" },
  "kind": "apt_package",
  "spec": { "name": "nginx" },
  "owners": ["ingress/edge-01"],
  "after": []
}
```

The agent uses `apt-get install -y` with the right env to suppress prompts.
Removal goes through `apt-get autoremove --purge` *if* the agent originally
installed the package; if the package was preexisting, removal is a no-op.

### `systemd_unit`

```json
{
  "id":   { "kind": "systemd_unit", "key": "nginx.service" },
  "kind": "systemd_unit",
  "spec": {
    "name":   "nginx.service",
    "enable": true,
    "active": true,
    "scope":  "system"
  },
  "owners": ["ingress/edge-01"],
  "after": [{ "kind": "file", "key": "/etc/nginx/sites-enabled/hello.example.com.conf" }]
}
```

- `enable` and `active` are independent: a unit can be enabled-but-stopped or
  active-but-disabled. The agent reconciles both.
- `scope` is `"system"` today. `"user"` (per-user units) is M3.
- `after` lets you express "this unit must be started after that file lands."
  Useful for handlers and ordering, see below.

### `quadlet`

A podman `.container` file. systemd's quadlet generator turns this into a
`<name>.service` unit at boot. Produced by `g.container` (and anything
that wraps it: `g.contrib.workload`, `g.contrib.web_service`, etc.).

```json
{
  "id":   { "kind": "quadlet", "key": "lila" },
  "kind": "quadlet",
  "spec": {
    "name": "lila",
    "body": "[Container]\nImage=ghcr.io/lichess-org/lila:latest\nPublishPort=9663:9663\n[Install]\nWantedBy=default.target\n"
  },
  "owners": ["workload/lila"],
  "after": []
}
```

The agent writes the file to `/etc/containers/systemd/<name>.container`,
runs `systemctl daemon-reload`, and lets the generator do its job. The
matching `systemd_unit` claim then enables/activates the generated unit.

### `nft_fragment`

A named nftables ruleset chunk dropped into `/etc/nftables.d/<key>.nft`,
included by the host's main ruleset, applied atomically. Produced by
`g.firewall` (today carried as a plain `file` claim with a handler
that reloads `nftables.service`; a dedicated `nft_fragment` provider
is on the agent roadmap).

```json
{
  "id":   { "kind": "nft_fragment", "key": "lila-allow" },
  "kind": "nft_fragment",
  "spec": {
    "name":  "lila-allow",
    "table": "Inet",
    "body":  "add rule inet golem input ip saddr 10.42.0.1 tcp dport 9663 accept\n"
  },
  "owners": ["service/lila"],
  "after": []
}
```

The agent applies fragments by writing the file and running `nft -f
/etc/nftables.d/<key>.nft`. On removal, it deletes the file and reloads
the parent ruleset.

### `dns_record`

An A / AAAA / CNAME / TXT / MX record on a configured zone. Produced
by `g.dns_record` (and `g.contrib.ingress` when `dns = true`). Emitted
on the host that carries the DNS role for the zone (typically tagged
`dns-primary`). Agent provider is M3.

```json
{
  "id":   { "kind": "dns_record", "key": "A:lichess.example.com" },
  "kind": "dns_record",
  "spec": {
    "zone":  "example.com",
    "name":  "lichess",
    "kind":  "A",
    "value": "203.0.113.10",
    "ttl":   300
  },
  "owners": ["ingress/edge-01"],
  "after": []
}
```

The agent calls the configured DNS provider's API. Capture-once-at-first-touch
records the prior record (or "did not exist") so removal restores the
zone honestly.

### `id`, `owners`, `after`

- **`id`** — globally unique within a bundle. `{kind, key}` together. Two
  claims with the same id is a bundle-rejection error.
- **`owners`** — free-form labels saying who declared this claim. Used for
  observability ("which workload is this for?") and for the `/v1/claims`
  inspection API. Not security-relevant; an unspecified `owners` is allowed.
- **`after`** — references to other claim ids that must apply first. Forms a
  DAG; cycles are rejected at acceptance time.

## `handlers`

When a *source* claim's content changes, restart the *target* units:

```json
{
  "source":  { "kind": "file", "key": "/etc/nginx/sites-enabled/hello.example.com.conf" },
  "targets": ["nginx.service"]
}
```

Handlers fire only on actual content change, not on bundle re-pushes that
leave the source's content identical. The agent compares the canonical-form
of the new spec to the journal's last_applied form; if they're byte-equal,
no handler fires.

## Canonical form

Bundle signing is over a **canonical JSON** representation:

- Object keys are sorted lexicographically at every level.
- Numbers serialize without trailing zeros.
- Strings are JSON-escaped using the standard rules.
- No trailing whitespace.

This is implemented in `crates/golem-types/src/canonical.rs` with an explicit
recursive walker — *not* by relying on `serde_json/preserve_order`, which is
a feature flag that can be enabled at the workspace level and silently break
signature stability.

If you write a bundle by hand and `golemctl sign` produces a signature that
doesn't verify, the most likely cause is a key-ordering mismatch. The signer
re-canonicalizes; the verifier re-canonicalizes; if they don't agree, your
JSON has a feature you didn't expect (NaN? Comments? UTF-8 BOM?).

<Aside type="note" title="Why not just protobuf?">
  Because the bundle is also the Nickel translator's output, and Nickel's
  natural export format is JSON. JSON-with-canonical-form is the lowest-friction
  path. If we ever need binary efficiency, the canonical form is already the
  bytes-on-the-wire — protobuf can wrap it later.
</Aside>

## What the agent does on receipt

Pseudocode for the accept path:

```
on POST /bundle:
  hold the bundle write-guard
  signed = parse_signed_bundle(body)
  verify_signature(signed)                  # → 400 if bad
  bundle = signed.bundle
  if bundle.node != self.node:        bail 400 "wrong node"
  if bundle.version <= last_applied:  bail 400 "monotonicity"
  validate_dag(bundle.claims)               # → 400 if cycle
  swap shared bundle slot
  return 202 { accepted_version: bundle.version }
```

The actual mutation happens on the next reconcile tick. Acceptance is a
*pure* swap — no apt, no systemctl, just JSON validation and a SQLite write.
That keeps the HTTP path fast and recoverable; if the agent crashes between
accept and the next tick, the bundle is durable in SQLite and gets applied
on restart.
