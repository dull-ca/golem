You don't need to read this to use golem. The
[config](/getting-started/the-config/) and [apply](/getting-started/applying/)
pages are enough. This page is for when something goes wrong and you want to
know what's actually happening, or when you're hacking on golem itself.

Internally, golem is three things stacked on each other. They're separated
because each has different change-frequency, different audience, and a
different failure mode.

## The config (input language)

What you write. Nickel, with two halves:

- **`app`** — services, volumes, env, references. Application-level. Doesn't
  know about boxes.
- **`deploy`** — nodes, expose, place, system escapes. Deployment-level.
  Doesn't know about your code.

This layer changes daily as you ship features. It's where typos and contract
violations get caught before bytes leave your laptop.

See [The config](/getting-started/the-config/) for the user-facing description.

## The translator (operator-side)

`golemctl` runs on your laptop. When you `apply`, it:

1. Reads the Nickel input and validates contracts.
2. Resolves all `{name.service}` and `g.ref.*` placeholders against the
   actual services declared.
3. Translates each service into a set of agent-level claims:
   - `services.api` becomes a `files["/etc/containers/systemd/api.container"]`
     claim with the rendered quadlet body, a `packages.podman` claim
     (idempotent across services), and a `units["api.service"]` claim that
     depends on the file claim.
   - `expose[].host` becomes a Caddyfile fragment + caddy package + caddy
     unit + a handler that reloads on Caddyfile change.
   - `volumes` and `system.*` translate similarly.
4. Computes a per-node bundle — only the claims that node owns.
5. Reads the agent's `/status` to get the last-applied version.
6. Signs the bundle with the operator's ed25519 key.
7. POSTs to the agent.

The translation is **deterministic** and **canonical**: the same input
produces byte-identical bundles. The agent's monotonicity check
(`version > last_applied`) requires this — re-signing the same input must not
break verification.

## The agent (system engine)

`golemd` runs on each box. ~3000 lines of Rust. Speaks three primitives only:

- **`files["/some/path"]`** — write a file with given content/mode/owner.
- **`packages.<name>`** — apt install / autoremove.
- **`units["foo.service"]`** — `systemctl enable --now`, `disable`, etc.

Plus the bookkeeping every claim needs: capture prior state before mutating,
journal it, mutate, journal "applied". When a claim is removed from a future
bundle, *unapply* it using the captured prior state. When a previously-installed
package was already on the box for another reason, leave it alone.

The agent deliberately does not know about services, exposes, volumes, or
anything at the config-language level. That keeps it small and the wire
format stable across config-language changes.

See [Honest convergence](/reference/honest-convergence/) for how the agent
stays honest after crashes.

## Why split it this way

| Concern | Lives in | Changes | Failure mode |
| --- | --- | --- | --- |
| What I'm running | The config (Nickel) | Daily | Operator catches it at apply time |
| How it lands on a box | `golemctl` (translator) | Per golem release | Bundle rejected at signing or by agent |
| What's actually on the box | `golemd` (agent) | Almost never | Crash → recover honestly on next tick |

The agent is the part that can corrupt your boxes. So it's the part we test
the hardest — every journal-before-mutate window has a `GOLEM_CRASH_AFTER`
injection point and a [smoke test](/reference/honest-convergence/) that
aborts the agent there.

## Where to look in the source

| Component | Path |
| --- | --- |
| Nickel schemas | `nickel/app.ncl`, `nickel/deploy.ncl`, `nickel/lib.ncl` |
| Translator | `crates/golemctl/` |
| Agent | `crates/golemd/` |
| Wire-format types | `crates/golem-types/` |
| Smoke test (real Debian container) | `crates/golemd/tests/smoke_install_remove.rs` |
| Smoke test (bash, with crash injection) | `smoke-test/run.sh` |
