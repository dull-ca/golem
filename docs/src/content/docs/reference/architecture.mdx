You don't need to read this to use golem. The
[config](/getting-started/the-config/) and [apply](/getting-started/applying/)
pages are enough. This page is for when something goes wrong and you want
to know what's actually happening, or when you're hacking on golem itself.

Internally, golem is two layers — Nickel composition on the operator
side, and a small Rust agent on each box. They're separated because they
change at different rates and have different failure modes.

## The Nickel toolkit (operator-side)

What you write. Nickel — a library of small primitives that compose
into per-host bundles.

**Primitives** (`nickel/primitives.ncl`):

- `g.file` — a file on disk.
- `g.package` — an apt package.
- `g.unit` — a systemd unit.
- `g.container` — a Podman Quadlet container (expands to a `.container`
  file + a systemd unit + a handler that restarts on change).
- `g.firewall` — an nftables rule fragment.
- `g.dns_record` — a DNS A/AAAA/CNAME/TXT/MX record.
- `g.site` — an nginx site config.

Each returns a `Fragment` — a record carrying `resources` (claims) and
`handlers` (restart-on-change triggers). Compose them with:

- `g.combine` — concatenate fragments.
- `g.own` — tag resources with a refcount key.
- `g.bundle_for` — walk an inventory and produce a per-host bundle,
  resolving cross-host placeholders.

**Composition** (`nickel/contrib.ncl`):

Higher-level shapes built from primitives. `g.contrib.workload` is
`package podman + container`. `g.contrib.web_service` adds a firewall.
`g.contrib.postgres` is `web_service` with the right image, port,
volume, env. None of this is in the schema — it's all just composed
primitives that you can read, copy, or replace.

**Reference resolution** (`nickel/resolve.ncl`):

`g.ref.service "name"` produces a placeholder string `{name.service}`.
At `bundle_for` time the resolver walks the inventory's `services`
declarations, finds which host owns each name, and substitutes
`vrack_ip:port` everywhere the placeholder appeared.

This whole layer changes daily as you ship features. It's where typos
and contract violations get caught before bytes leave your laptop.

## `golemctl` (the operator CLI)

The CLI is small. It:

1. Calls `nickel export --format json` on `(import "config.ncl").bundle_for "node-name"`,
   producing one Bundle per host.
2. Reads each host's `/status` to get the last-applied version; assigns
   `max(last_applied) + 1` across the apply set.
3. Signs each bundle with the operator's ed25519 key.
4. POSTs to each host's agent.

Translation logic itself lives in Nickel — `golemctl` doesn't know what
a workload, container, or firewall is. It just evaluates Nickel and
ships the result.

The translation is **deterministic** and **canonical**: the same input
produces byte-identical bundles. The agent's monotonicity check
(`version > last_applied`) requires this — re-signing the same input
must not break verification.

## The agent (system engine)

`golemd` runs on each box. ~3000 lines of Rust. Speaks a small set of
primitives:

- **`File`** — write a file with given content / mode / owner.
- **`AptPackage`** — apt install / autoremove.
- **`SystemdUnit`** — `systemctl enable --now`, `disable`, etc.
- **`Quadlet`** — a podman .container file (translated by systemd into
  a service unit).
- **`NftFragment`** — *future*. Currently nftables fragments ride as
  plain `File` claims with a handler that reloads `nftables.service`.
- **`DnsRecord`** — *future* (M3).

Plus the bookkeeping every claim needs: capture prior state before
mutating, journal it, mutate, journal "applied". When a claim is
removed from a future bundle, *unapply* it using the captured prior
state. When a previously-installed package was already on the box for
another reason, leave it alone.

The agent deliberately does not know about workloads, services,
ingress, or anything at the config-language level. That keeps it small
and the wire format stable across config-language changes.

See [Honest convergence](/reference/honest-convergence/) for how the
agent stays honest after crashes.

## Why split it this way

| Concern | Lives in | Changes | Failure mode |
| --- | --- | --- | --- |
| What I'm running | The Nickel inventory | Daily | Operator catches it at evaluation |
| How it lands on a box | `nickel/primitives.ncl` + `contrib.ncl` | Per golem release | Bundle rejected at signing or by agent |
| What's actually on the box | `golemd` (agent) | Almost never | Crash → recover honestly on next tick |

The agent is the part that can corrupt your boxes. So it's the part we
test the hardest — every journal-before-mutate window has a
`GOLEM_CRASH_AFTER` injection point and a
[smoke test](/reference/honest-convergence/) that aborts the agent
there.

## Where to look in the source

| Component | Path |
| --- | --- |
| Public Nickel API | `nickel/lib.ncl` |
| Primitives | `nickel/primitives.ncl` |
| Composition (Fragment, combine, own) | `nickel/fragment.ncl` |

| Bundle assembly | `nickel/bundle.ncl` |

| Agent | `crates/golemd/` |
| Wire-format types | `crates/golem-types/` |
| Smoke test (real Debian container) | `crates/golemd/tests/smoke_install_remove.rs` |
| Smoke test (bash, with crash injection) | `smoke-test/run.sh` |
