The shape of every golem deploy is the same: an inventory of hosts,
each carrying an array of `fragments` — small composable units built
from primitives like `g.container`, `g.firewall`, `g.site`. This guide
is that shape at its smallest. One host. One container behind one
public hostname.

## The whole thing

```nickel
let g = import "../../nickel/lib.ncl" in

let inventory = {
  hosts = {
    "box-01" = {
      public_ip = "203.0.113.10",
      vrack_ip  = "10.42.0.1",
      fragments = [
        # The container — and the firewall + ingress around it.
        g.contrib.web_service {
          name  = "hello",
          image = "ghcr.io/example/hello:v1",
          port  = 8080,
          allow = ["10.42.0.1"],
        },

        # Public HTTPS termination. Owns the DNS record.
        g.contrib.ingress {
          host     = "hello.example.com",
          upstream = "%{g.ref.service "hello"}",
          dns      = true,
          dns_ip   = "203.0.113.10",
        },
      ],
      services = [{ name = "hello", port = 8080 }],
    },
  },
} in

{ bundle_for = g.bundle_for inventory }
```

That's the deploy. One host with one workload (the container + its
firewall + the matching service-name registration) and one ingress.

- **`g.contrib.web_service`** combines `g.package "podman"` +
  `g.container` + `g.firewall`. It's a workload that listens on a port
  with firewall rules. Read `nickel/contrib.ncl` if you want to see how
  it's built — it's about 12 lines.
- **`g.contrib.ingress`** combines `g.package "nginx"` + `g.unit
  "nginx.service"` + `g.site` + (optionally) `g.dns_record`. Public
  HTTPS via nginx with the DNS record golem owns.
- **`g.ref.service "hello"`** resolves to `10.42.0.1:8080` at
  translation time — the resolver finds which host owns the `hello`
  service (this same box) and which port it's on.
- **`services = [{ name = "hello", port = 8080 }]`** registers the
  service-name → port mapping for the resolver.

## Apply it

<Steps>
1. From the operator's laptop:

   ```bash
   golemctl apply config.ncl operator.sk host-addrs.json
   ```

2. Wait one tick (the agent reconciles every 30s by default):

   ```bash
   curl -s http://10.42.0.1:7474/status | jq
   ```

3. Hit the hostname. The DNS record is live, TLS is provisioned, traffic
   reaches your container:

   ```bash
   curl https://hello.example.com
   ```
</Steps>

## What golem produced under the hood

The Nickel evaluation produces a Bundle for `box-01` with roughly nine
claims that the agent then applies:

| Claim | Why |
| --- | --- |
| `apt_package: podman` | Required for any container. |
| `file: /etc/containers/systemd/hello.container` | The Quadlet definition. |
| `systemd_unit: hello.service` | Auto-generated by systemd from the quadlet. |
| `file: /etc/nftables.d/hello-allow.nft` | Firewall rule allowing port 8080 only from `10.42.0.1`. |
| `apt_package: nginx` | For the ingress. |
| `file: /etc/nginx/sites-enabled/hello.example.com.conf` | The nginx site block routing `hello.example.com` to the `hello` service. |
| `systemd_unit: nginx.service` | Enabled and active. |
| `dns_record: hello.example.com A` | A record pointing at `203.0.113.10`. |

You don't write any of that — the primitives produce it. The agent
journals each claim's prior state before mutating, so removing them
later restores the box honestly. That's the part that makes golem
worth using over a shell script.

## Take it back

Edit the Nickel to empty the fragments:

```nickel
"box-01" = {
  public_ip = "203.0.113.10",
  vrack_ip  = "10.42.0.1",
  fragments = [],
}
```

After the next tick:

- `hello.service` and `nginx.service` are stopped and disabled, the
  unit files removed.
- The Quadlet `.container` file is removed.
- The nginx site config and nftables fragment are removed.
- The DNS record is deleted.
- Both `podman` and `nginx` are removed via `apt-get autoremove` —
  *only because* golem captured `preexisting: false` for each when it
  first installed them. If either was already on the box for another
  reason, the unapply leaves it alone.
- The journal in `/var/lib/golem/state.db` is empty.

The empty journal is the proof that nothing leaked. Honest unapply is
what makes golem safe to use on a box you also touch by hand. See
[Honest convergence](/reference/honest-convergence/) for how this stays
honest even across crashes.
