The shape of every golem deploy is the same: an `Inventory` of `Hosts`,
each carrying `workloads` (containers), `services` (port routing with
firewall), and `ingress` (public HTTPS). This guide is that pattern at
its smallest. One host. One workload. One service. One hostname. Golem
owns the DNS record.

## The whole thing

```nickel
let g = import "../../nickel/lib.ncl" in

{
  hosts = {
    "box-01" = {
      name      = "box-01",
      public_ip = "203.0.113.10",

      workloads = [
        { name = "hello", image = "ghcr.io/example/hello:v1" },
      ],

      services = [
        { name = "hello", workload = "hello", port = 8080,
          allow_from = ["box-01"] },
      ],

      ingress = [
        { host = "hello.example.com", backend = "hello", dns = true },
      ],
    },
  },
} | g.Inventory
```

That's the deploy. One host with one workload, one service, one ingress.

- **`workloads`** — the container. The image is whatever you're shipping.
- **`services`** — names port `8080` on the `hello` workload as the
  service `hello`, with `allow_from = ["box-01"]` (only this box itself
  can reach the port). The firewall is closed to the outside; nginx
  (running on the same box) is what the world hits.
- **`ingress`** — `hello.example.com` is fronted by nginx, terminating
  TLS via Let's Encrypt and reverse-proxying to the `hello` *service*.
  `dns = true` makes golem own the A record pointing
  `hello.example.com` at `203.0.113.10`.

## Apply it

<Steps>
1. From the operator's laptop:

   ```bash
   golemctl apply config.ncl operator.sk host-addrs.json
   ```

2. Wait one tick (the agent reconciles every 30s by default):

   ```bash
   curl -s http://10.42.0.1:7474/status | jq
   ```

3. Hit the hostname. The DNS record is live, TLS is provisioned, traffic
   reaches your container:

   ```bash
   curl https://hello.example.com
   ```
</Steps>

## What golem did under the hood

The translator unfolded those nine lines into roughly nine layer-3
claims that the agent then applied:

| Claim | Why |
| --- | --- |
| `apt_package: podman` | Required for any workload. |
| `quadlet: hello` | Defines the `hello` container. |
| `systemd_unit: hello.service` | Auto-generated from the quadlet, enabled and active. |
| `nft_fragment: hello-allow.nft` | Firewall rule allowing port 8080 only from `box-01`. |
| `apt_package: nginx` | Required because `ingress` is non-empty. |
| `file: /etc/nginx/sites-enabled/hello.example.com.conf` | Site block routing the hostname to the `hello` service. |
| `systemd_unit: nginx.service` | Enabled and active, with a handler that reloads on site change. |
| `nft_fragment: nginx-allow.nft` | Firewall rule allowing 80/443 from anywhere. |
| `dns_record: hello.example.com A` | A record pointing at `203.0.113.10`. |

You don't write any of that. The agent journals each claim's prior
state before mutating, so removing them later restores the box honestly.
That's the part that makes golem worth using over a shell script.

## Take it back

Edit the Nickel to empty out `workloads`, `services`, and `ingress`,
then re-apply:

```nickel
"box-01" = {
  name      = "box-01",
  public_ip = "203.0.113.10",
}
```

After the next tick:

- `hello.service` is stopped and disabled, the quadlet is removed.
- `nginx.service` is stopped, the site file is removed.
- The nft fragments are removed.
- The DNS record is deleted.
- Both `podman` and `nginx` are removed via `apt-get autoremove` —
  *only because* golem captured `preexisting: false` for each when it
  first installed them. If either was already on the box for another
  reason, the unapply leaves it alone.
- The journal in `/var/lib/golem/state.db` is empty.

The empty journal is the proof that nothing leaked. Honest unapply is
what makes golem safe to use on a box you also touch by hand for other
reasons. See [Honest convergence](/reference/honest-convergence/) for
how this stays honest even across crashes.
