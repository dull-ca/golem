## What it is

Golem is two things:

- **A Nickel toolkit** — small primitives like Ansible modules
  (`g.file`, `g.package`, `g.container`, `g.firewall`, `g.site`,
  `g.dns_record`) that you compose into whatever shape fits your fleet.
  Some compositions ship in `g.contrib` (`workload`, `web_service`,
  `postgres`, `redis`, `mongo`) — read them, copy them, replace them.
  The schema doesn't predict your fleet; you predict your fleet.
- **An agent** — `golemd` runs on each box, accepts signed per-host
  bundles from `golemctl`, and reconciles the box's actual state
  against them.

The smallest interesting deploy is *twelve lines*. No YAML, no Helm
chart, no ConfigMap, no operator-CRD.

Most of golem's value is in what you *don't* write. You don't write
port mappings — `{db.service}` resolves at translate time. You don't
keep a separate `volumes:` block in sync with the container that owns
the volume. You don't write firewall rules separately from the
container they protect — `g.firewall { allow = [edge_ip] }` IS the
rule. You don't run a DNS tool alongside golem — `dns = true` on an
ingress IS the record. And the abstractions you build (`postgres`,
`celery_worker`, `litour_service`) are *yours*, not golem's.

    outage.
  </Card>
  <Card title="Tiny agent, small wire format" icon="seti:lock">

    changes.
  </Card>
  <Card title="Two binaries, no control plane" icon="seti:default">

    signatures between them. No etcd, no Swarm manager, no operator
    pattern, no CRDs, no API server to keep up.
  </Card>

## And it's correct

The agent is small (~3000 lines of Rust) and engineered for one property:
**after any number of crashes, the next clean tick converges to a state
that matches the OS.** Every claim journals its prior state before
mutating; removing a claim restores what was there before; the
[crash-injection smoke test](/reference/honest-convergence/) verifies
recovery at every window. That's the floor — necessary, not the pitch.

## Status

Golem is being built in milestones. M1 (the layer-3 engine — files,
packages, systemd units) is implemented and integration-tested. M2
(the Nickel toolkit with primitives, contrib, ingress, secrets) is in
progress.

The docs ship the full vision; pages flag which milestone covers which
feature. See [Status & milestones](/reference/status/) for the current
state.
