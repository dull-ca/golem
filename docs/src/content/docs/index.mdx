## What it is

Golem is two things and that's it:

- **An input language** — write your fleet as an `Inventory` of `Hosts`
  in [Nickel](https://nickel-lang.org), each carrying `workloads` (the
  containers), `services` (internal port routing with a firewall), and
  `ingress` (public HTTPS with first-class DNS). The smallest
  interesting deploy is *twelve lines*. No YAML, no Helm chart, no
  ConfigMap, no operators-CRD.
- **An agent** — `golemd` runs on each box, accepts signed per-host
  bundles from `golemctl`, and reconciles the box's actual state
  against them.

Most of golem's value is in what you *don't* write. You don't write port
mappings — `{db-01.host}` resolves at translate time. You don't keep a
separate `volumes:` block in sync with the container that owns the
volume. You don't write firewall rules separately from the services they
protect — `allow_from = ["edge-01"]` IS the rule. You don't run a DNS
tool alongside golem — `dns = true` on an ingress IS the record. You
don't split your config into ten YAML files glued together by
`kustomize` because the language is expressive enough to express the
thing once.

## Why it's different

<CardGrid>
  <Card title="Twelve lines, not two hundred" icon="seti:default">
    Postgres + Django + caddy in twelve lines. No deploy descriptors per
    service, no `kind:` everywhere, no `selector:` matching `labels:` matching
    `name:`. The language tells you everything that's running and how it's
    wired.
  </Card>
  <Card title="Statically checked" icon="approve-check">
    Misspell `{db-01.hsot}`? Forget the `port` field on a service?
    Reference a host or group that doesn't exist? `golemctl apply`
    rejects it before bytes leave your laptop. Errors find you in
    seconds, not in an outage.
  </Card>
  <Card title="Composable, not packaged" icon="puzzle">
    A service is just a record. `lila & { name = "lichess",
    env.FEATURE_FLAGS = "canary" }` clones the template with overrides
    — no inheritance, no forking. The same template runs on staging,
    prod, and a single-box dev rig.
  </Card>
  <Card title="Two binaries, no control plane" icon="seti:lock">
    `golemctl` on your laptop, `golemd` on each box, ed25519 signatures
    between them. No etcd, no Swarm manager, no operator pattern, no CRDs,
    no API server to keep up.
  </Card>
</CardGrid>

## And it's correct

The agent is small (~3000 lines of Rust) and engineered for one property:
**after any number of crashes, the next clean tick converges to a state
that matches the OS.** Every claim journals its prior state before mutating;
removing a claim restores what was there before; the
[crash-injection smoke test](/reference/honest-convergence/) verifies recovery
at every window. That's the floor — necessary, not the pitch.

## Status

Golem is being built in milestones. M1 (the layer-3 engine — files, packages,
systemd units) is implemented and integration-tested. M2 (the Nickel input
language with containers, ingress, volumes, secrets) is in progress.

The docs ship the full vision; pages flag which milestone covers which feature.
See [Status & milestones](/reference/status/) for the current state.
