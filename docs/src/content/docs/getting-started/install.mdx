Two binaries: `golemctl` (operator-side, runs on your laptop) and `golemd`
(agent, runs on each node).

<Aside type="caution" title="What you need">
  - A Debian trixie box (or container) for the agent.
  - A laptop with the Rust toolchain to build the binaries.
  - sudo on the agent node.
</Aside>

## 1 — Build static binaries

The repo has a `build-static.sh` that produces musl-linked binaries you can
scp to any Debian box:

```bash
git clone https://codeberg.org/dull/golem
cd golem
./build-static.sh
```

Output lands at `target/x86_64-unknown-linux-musl/release/{golemctl,golemd}`.

## 2 — Generate an operator keypair

This is the ed25519 key the agent will trust. Treat it like an SSH private key.

```bash
./target/x86_64-unknown-linux-musl/release/golemctl keygen ./operator
```

You get two files:

- `operator.sk` — private signing key, mode `0600`.
- `operator.pk` — public verifying key (hex), shipped to every node.

## 3 — Install the agent on a node

<Steps>
1. Copy the public key onto the box and put it where the agent looks:

   ```bash
   sudo install -d -m 0755 /etc/golem
   sudo cp operator.pk /etc/golem/trusted-keys
   ```

2. Install the binary and the systemd unit:

   ```bash
   sudo install -m 0755 \
       target/x86_64-unknown-linux-musl/release/golemd \
       /usr/local/bin/

   sudo install -m 0644 packaging/golemd.service /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable --now golemd
   ```

3. Confirm it's running:

   ```bash
   curl -s http://127.0.0.1:7474/healthz
   # → ok
   ```
</Steps>

## 4 — Listen address & networking

The default listener is `127.0.0.1:7474`. The agent only authenticates
**bundles**, not network connections, so:

- For single-node fiddling, leave it on localhost and use SSH port-forwarding.
- For a real fleet, run on a Nebula tunnel or bind to a unix socket. The
  `--listen` flag takes any `SocketAddr`.
